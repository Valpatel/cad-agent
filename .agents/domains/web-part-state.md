# Part checklist ownership

Part identities are stable project keys, not table positions or display labels. Sorting/filtering retains row nodes and status ownership; replacing a table requires disposing its enhancer and progress controls. A pending file decode must validate its generation and disposal state before mutating the tracker or DOM. Shared trackers may outlive individual table controls, so disposal of the latter still invalidates their imports.

Imports validate the entire project/schema/Boolean payload before merging. Unknown identities may be retained for future project revisions, but unsupported fields, unsafe keys, invalid types and oversized merged state fail atomically. Storage denial preserves useful in-tab state with an explicit export reminder. These are personal checklist marks, not a purchasing service or quantity ledger.
