# A cloud session reaches GitHub through MCP tools, not `gh`

On 2026-11-15 UTC one orchestrating cloud session and its subagents worked on #749, #752, #753, #755 and #756 from a
claude.ai cloud container. Durable guidance: [cad-remote-runs, working from a cloud container](../../skills/cad-remote-runs/SKILL.md#working-from-a-cloud-container).
Each section below says whether it was confirmed against GitHub records or observed once.

## Push and issue creation return 403 while clone and read work

**Symptom:** reads, clones and fetches succeed; a push or an issue creation fails with "Claude doesn't have GitHub
access to `<repo>` for your organization". **Cause:** the repositories are public, so reads need no grant; writes need
the Claude GitHub App installed on the organization with access to that repository. **Action:** ask the owner to
install or extend the app (the container's own documentation names the settings page); do not retry or route around
it. **Limits:** observed once, not confirmed: no GitHub record keeps the refused call. Later the same session's
pushes and PRs (#749, #752, #753, #755, #756) succeeded.

## No usable `gh`, so the local live-gate run cannot happen

**Symptom:** `gh` is missing, or present with `The token in GH_TOKEN is invalid` (`gh auth status`, checked again on
2026-11-15 in the same container). **Cause:** the container offers the GitHub MCP tools instead; `tools/ci_gates.py`
shells out to `gh`. **Action:** read and write through the MCP tools; the substitute for the local
`tools/ci_gates.py all` run is dispatching the Gates workflow on `dev`, which [#750](https://github.com/Valpatel/cad-agent/issues/750)
proposes (PR #755, open on 2026-11-15). Until that merges, follow the current [review skill](../../skills/cad-pr-review/SKILL.md)
and leave a merge that needs the local run to a `gh` session or the owner. **Limits:** the invalid token was confirmed;
whether `gh` exists varies with the container image.

## A pass verdict is stored but the review gate reports "no review verdict yet"

**Symptom:** `cad-gates/dev/review` keeps reporting "no review verdict yet" although an independent pass review for the
head is posted. **Cause:** the cloud posting path appends `---` and an italic "Generated by" footer after every body,
and `marker()` on `dev` accepts the marker only as the last non-empty line. **Evidence:** PR #749 reviews 5912399621
and 5912414328 both end with the marker and then the footer; gate runs 43751710673 and 43751767040; on #752 review
5912494512 on head `c49a88f8` was likewise unread (5912461649 was for an earlier head, so it could not count for
the current one even if read; [PR comment](https://github.com/Valpatel/cad-agent/pull/752#issuecomment-6900205193)).
**Action:** do not post more copies and do not merge around the gate. Until [#751](https://github.com/Valpatel/cad-agent/issues/751)
(PR #752, open on 2026-11-15) merges, a verdict from a cloud session cannot count: a review whose last line is the
marker must come from github.com or a `gh` session. **Limits:** confirmed from the stored review bodies.

## Editing a PR description restarts CI at the same head

**Symptom:** a CI run is cancelled and a new one starts with no new commit. **Evidence:** on #752 run 43753179618
(head `c49a88f8`) was cancelled and run 43753484298 started at the same head; the earlier record is
[the 2026-10-29 incident](../2026-10-29-pr-description-edits-restart-ci.md) and #559. **Action:** finish the body
before the final CI wait and post status as comments ([review publication](../../playbooks/review-publication.md)).
**Limits:** confirmed that the same-head run was cancelled and replaced; the edit that caused it is the session's
account, not a GitHub record.

## GitHub MCP quirks

- **Thread replies create empty reviews.** Replying to a review thread stored a `COMMENTED` review with no body
  (#749: 5912408743, 5912409218, 5912409622). The gate ignores them, since they carry no marker. Confirmed.
- **`list_issues` cursor pagination** failed intermittently with "Resource not accessible by integration".
  Observed once, not confirmed.
- **A "check suite completed" event can name an older head** than the PR's current one. Compare its SHA with the
  PR's head before acting on it. Observed once, not confirmed.
