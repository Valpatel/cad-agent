# Source records need their actual published namespace

Search found [repository ownership and served namespaces](../2026-11-06-source-selection-must-not-pass-empty.md#keep-repository-ownership-separate-from-served-namespaces). This records a new concrete verifier mistake from #427.

**Evidence, 2026-11-07 UTC:** the first v0.25.1 public probe fetched `/docs/img/gyropup/SOURCE.json` from the website and received404 after11 retained raw responses, with zero view/context acceptance. The released builder at main `a32c1e6700ab3c64f08c1f5441f01303498e103d` copies only SVG/PNG/JPEG/GIF/WebP from `docs/img`; it never promised a website JSON route. The four ordinary model/card assets already matched released Git. Independent review accepted the exact namespace correction: obtain SOURCE through immutable `raw.githubusercontent.com/Valpatel/cad-agent/<actual-main>/docs/img/gyropup/SOURCE.json`, asserting exact final URL, no redirect and released Git bytes. The four actual website assets and all source/model/banner bindings stayed unchanged ([review](https://github.com/Valpatel/cad-agent/issues/427#issuecomment-6705108925)).

**Cause:** the verifier inferred a public route from repository ownership instead of reading the pinned producer's copy contract. The404 was a verifier namespace error, not evidence of a product, cache or deployment failure.

**Recorded request/output:** `GET https://cad-agent.valpatel.com/docs/img/gyropup/SOURCE.json` →404; corrected `GET https://raw.githubusercontent.com/Valpatel/cad-agent/a32c1e6700ab3c64f08c1f5441f01303498e103d/docs/img/gyropup/SOURCE.json` →200,1308 bytes, SHA256 `12e50e9bc8ddb85f1293692a51e95d2638e283d5d1da26fd65018d12c090568e`. Both were retained by the actual Node HTTP consumer before assertions, not inferred from URL strings.

**Rule:** derive each expected artifact location from the released producer. Distinguish ordinary served assets from immutable source metadata; record both hosts/routes explicitly. Keep source metadata byte binding and actual ordinary-site asset comparisons. Save raw failures before assertions and preserve the original failed attempt when correcting the recipe.

**Limits:** a correct immutable source record does not prove the website served its associated model. Those four ordinary assets, actual viewer controls and both stable deployment revisions were separately checked in the complete accepted run ([actual acceptance](https://github.com/Valpatel/cad-agent/issues/427#issuecomment-6705278005)). No site route or cache setting was changed.

## Shared discovery must preserve the source model it projects

**Design checkpoint, 2026-11-12 UTC, #599.** Actual main `62187386` (the same tree as dev `a2d356de`) publishes 228 catalogue entries and 814 reference records. Catalogue search indexes card summaries rather than article sections: `counterbores` and `disassembly` return no cards despite their presence in Pitfalls and the requirements lesson. “Tools” names both a catalogue of CLI commands and a long command/Python API manual. Six external URLs occur in both catalogue and reference records with different adoption/read meanings; URL equality is not permission to collapse those records.

**Bounded design.** Make `/explore` the primary navigation entry; retain `/catalog` as its clearly linked deeper catalogue/compatibility view. Add an explicitly derived discovery projection from current catalogue items, canonical lesson/pitfall sections and all reference records, using the existing topic tree. Reuse `<cad-gallery>` for search, topic/type filters, URL state, accessible counts and compact grouped defaults. Show references as concise rows, not hundreds of large picture cards; use existing source-owned visuals for orientation. Results retain their canonical page/section/record destinations and clear type labels. Preserve current catalogue/reference machine feeds, IDs, aliases, Markdown twins and legacy filter URLs; do not promote records or merge evidence, adoption and area maturity. Simplify top navigation while keeping old routes reachable.

**Interfaces.** A compiler-owned `site-discovery.mjs` will build the derived projection and compact HTML from existing catalogue output, published page HTML and the reference compiler's loaded model. New machine output is separately named/schema-versioned, not a mutation of `catalog.json`. The catalogue compiler retains its existing compatibility view for old kind/status/licence/maturity links. No search service, dependency, remote runtime fetch or hand-maintained second content registry.

**Meaningful experiment/check plan.** Test actual producer output, not only fixtures: a hidden body incident must become discoverable with a stable deep link; every canonical reference occurs exactly once in the projection; all source feeds/records retain their identities and counts; shared URLs retain separate source/adoption labels. Negative controls cover absent terms, unknown topics, invalid URLs/markup and snippet-only records masquerading as checked evidence. Check inherited catalogue filters/history, reference deep links/filters, no-script fallback, keyboard/mobile controls, density and source readability. Reserve a capped browser lane for 320 px and desktop light/dark checks and use existing width/readability predicates on actual prerendered assets. Independent experiments and exact-head GPT-6 review precede any merge; normal CI and public release proof remain required.

**Limits.** This is discovery and presentation, not another knowledge promotion, manufacturing API or universal full-text search claim. The existing source tables and source-evidence boundaries remain authoritative. Work is tracked under #599; the shared coordinator lease is not released by this author.

**Prototype evidence, #599:** the original derived feed at `/catalog/discovery.json` failed the existing catalogue-area consumer (which enumerates `/catalog/*.json` as area-schema files). The separately versioned projection moved to `/discovery.json`; no old schema/consumer exemption was added. Independent original-CSP preview also exposed absolute canonical demo-cover URLs in local/alternate-origin HTML. Keep canonical URLs in machine data, but emit same-origin paths for site-owned image markup and require `complete && naturalWidth > 0`; URL remapping or a visible image box is not load proof. Early no-script topic/type controls reloaded an unfiltered list and the fallback exposed 1199 links over 115000 px. Native collapsible groups now retain actual source links while JavaScript-only controls hide, rather than pretending query-only navigation filters static HTML.

**Loader-failure boundary, #599:** the corrected no-script view still failed when `/web/site.js` itself was blocked. JavaScript was enabled, so the catalogue's first-paint CSS hid overview overflow rows; the missing loader could not set `data-failed`. In Explore only, enhancement controls now remain hidden and native groups retain their full contents until `data-ready`. Test both the top-level loader and the gallery module failing, as well as JavaScript being disabled; a downstream failure handler cannot establish the upstream loader's fallback. The existing catalogue's first-paint contract is unchanged.

**Default-view reading measurement, #599:** the improved preview still failed the unchanged whole-page reading check: 2175 px with zero qualifying visuals, because its 110 × 80 px thumbnails were below the existing 120 × 80 px visual definition. The correction enlarges actual example thumbnails, uses two compact results per type in a two-column desktop browsing overview, and avoids repeating the already-present demo strip as another default list. Focused queries and explicit type views retain their original result flow. This is a readability/layout change, not a new visual exception, font reduction or adjusted reading threshold; acceptance must remeasure the existing predicate on the real producer.

**Independent final acceptance, #599 at `d3668afc`:** the real corrected view measured 1716 px desktop height, 2891 px phone height, eight compact default rows and three loaded qualifying example images. The unchanged reading predicate measured 955 px against 1200 px, with no overflow. Focused counterbores search retained its three practical entries and one source; all three script/failure modes preserved native access to the exact PEM record without dead controls. The owned bounded browser unit was inactive with an empty control group. [Recoverable public receipt](https://github.com/Valpatel/cad-agent/issues/599#issuecomment-6811832942). This is UI/source-navigation evidence, not another source read, promotion or physical qualification.

## Discovery and reading need one topic shell

**Design and test plan, 2026-11-12 UTC, #603.** The owner chose guides inside the same Explore layout and topic tree. The preceding #599 release made search coherent, but reading a result still leaves discovery for a separate flat section list; the Full catalogue destination retains a competing entrance. The right outline also inherits only foreground/muted theme tokens, so its hover can use the kit's pale default in dark mode. Footer dates currently discard the recorded commit time.

### Implementation boundary

- Extend the static compiler and existing gallery/nav components. No SPA, remote search service, dependency, source promotion or new manufacturing capability.
- Build one reusable topic-tree projection from `docs/areas.yaml` domain/area hierarchy and existing page/catalogue placement. A page can appear in relevant topics without duplicating its source identity. Keep an explicit cross-cutting group for pages not assigned to one process and a separate repository-map path.
- Explore remains the sole discovery entrance. Its nested topic tree, catalogue glyphs and useful type/source/adoption/compatibility facets lead to results or a focused reading view. Remove visible area maturity scores/bars/filters; machine data retains original fields and semantics.
- Reading pages retain their real current URLs, fragments, Markdown twins and article HTML. Surround them with the same Explore topic navigation and a compact search/back context; a dedicated right outline remains local to the article. Shared chrome must not inflate the article's reading width or bury its heading on phones.
- Absorb useful catalogue browsing into Explore. Old `/catalog` and its filtered/bookmarked URLs must remain meaningful, including canonical item anchors. Keep original JSON schemas, item IDs/aliases and external destinations. Compatibility is deliberate, not a blanket redirect that drops state or fragment.
- Complete the right outline's shared theme-token binding. Verify normal, hover, focus and current states in light/dark without lowering existing contrast thresholds.
- Format full recorded commit timestamps in `America/Los_Angeles` with an explicit PST/PDT label and a complete machine-readable `datetime`. Date-only source metadata must remain date-only; source update, build time and release revision are separate facts.

### Meaningful validation

1. Pure compiler/gallery tests: one shared hierarchy on browse/reader routes, real parent-child placement, icon reuse, visible maturity absence, preserved source counts/IDs/aliases and machine schema/data. Plant wrong topic placement, dropped compatibility query/anchor and erased timestamp controls where existing harnesses support them.
2. Route and link contracts: canonical old article/item anchors and filtered catalogue links remain usable; result-to-article navigation stays in the Explore shell. Legacy Markdown and JSON remain unchanged except release revision/build metadata.
3. Existing browser harness: update obsolete contracts to the new explicit design; retain visibility, keyboard, geometry, contrast, no-script and failure controls. Test dark outline hover/focus/current with the actual predicate and a failing-before fixture.
4. Coordinated bounded visual checks at desktop and phone: browse → nested topic → guide → local outline → search/back, useful compatibility filters, deep bookmarks, native no-JS navigation, readable article width and loaded glyphs/images. Measure initial height/DOM/payload and existing reading-wall predicate. No allowlist or threshold relaxation.
5. Exact-head independent GPT-6 review and normal current-head CI precede integration. Main/public primary-site acceptance precedes closing #603; alias registrar scope remains separate.

### Operational rule and limits

Inspect script parsing before invocation, including `--help`. Local producer commands use explicit existing Node 22 and `--client-diagrams` inside a reserved owned cap; never infer browser-free execution from a broad test filename or `CAD_AGENT_SITE`. Coordinate the browser lane first. Do not replay prior spent release/retirement operators. Keep the coordinator-managed claim active until it is explicitly completed by its owner.

This plan promises a bounded navigation/readability feature. It does not establish source evidence, physical qualification, universal search coverage or public deployment before the corresponding receipts exist.

**Prototype measurement:** rendering every catalogue note, cover and related-link list inside Explore produced 1,097,016 raw bytes / 151,329 gzip bytes / 10,035 start tags. This duplicated the existing catalogue feed and exceeded the compact-view contract. Keep default search metadata compact: rich catalogue details enhance a native disclosure from the same-origin, revision-bound existing `/catalog.json` only when opened. The legacy compatibility view retains its static full entries and old bookmarks; ordinary Explore users do not need that route. Keep the original absolute payload safeguards; measure before granting any representation budget. This is not a new search index or an evidence promotion.

### A document rail needs the same complete theme contract as its tree

**Observed baseline, 2026-11-12 UTC, #603:** independent actual-public-main `d27a3164` measurement of the toolkit's “Honest evidence” right-outline link reported 17.58:1 normal dark contrast but 1.0193:1 when hovered. The hovered foreground was `rgb(238,242,248)` on the kit's fallback `rgb(238,241,228)` background; `--cad-nav-hover` was empty. Light hover was 13.02:1. The left navigation and right outline both consume kit nav styles, but only `cad-nav` received the complete site-theme token binding.

**Corrective rule:** bind the same foreground, background, hover, current, accent and line tokens to both consumers. A readable resting link does not establish hover/focus/current readability. The existing whole-page WCAG predicate is shared with targeted outline-state checks, including a planted pale-background negative; its 4.5:1 normal-text threshold is unchanged. Keep the exact recorded commit instant in the footer and format it in the named Pacific timezone rather than truncating it or assuming a fixed UTC offset.

**Compatibility/testing limits:** the new hierarchy uses one page-placement/ancestor projection for topic links and result facets. Saved legacy type/status/licence/demo/maturity filters and maturity sorting remain data behavior, with no normal maturity UI. Old item/group fragments must reveal the actual row, not merely exist as invisible IDs. The old flat-card, maturity-bar and modal-sheet browser assertions are replaced by the new shell's real filter/bookmark/history/native-disclosure contracts; hostile URL/data, early/late gallery failure, no-JS/module/top-loader failure and unchanged reading/contrast thresholds remain tested. Local pure checks do not establish hosted WebKit or final public acceptance.

### Keep canonical plain text out of an HTML-summary extractor

**Hosted evidence, 2026-11-12 UTC, #604:** Chromium's hostile-registry test failed at source `d0b6d70b`: `the what line shows as text`. Its actual compatibility row retained the escaped name, licence, policy and quoted attributes, but the description was only `&quot;&gt;`. No executed injection was demonstrated. Reusing the compact discovery summary in the legacy catalogue had passed canonical plain `what` text through the HTML extractor, which stripped literal tag-like source text before output escaping.

**Correction:** render the legacy full description from canonical `c.what` as plain text and escape it at the HTML boundary. Keep the compact discovery projection's existing semantics separate; do not silently rewrite its JSON. The existing hostile fixture retains its literal name/description and whole-page/attribute/cover safety assertions, adds literal notes/licence-notes and explicit JSON/date/star attribute controls, and preserves opt-in hash-bound generated evidence before removing its own scratch worktree.

**Command and scope:** the exact fixture is selected with `node --test --test-name-pattern='^outside data cannot inject markup:' tests/site/website-catalog.test.mjs`, against a completed explicit client-diagram producer. Its separate scratch producer now explicitly uses `--worktree --client-diagrams` and asserts the actual `0 drawn` build output. This case checks escaped HTML, attributes, canonical JSON and original SVG covers; it does not establish prerendered diagram readability. Other fixture builders still need individual inspection and execution caps. Preserve old failure evidence and require fresh current-head normal CI and independent review; do not skip the fixture or weaken its security conditions.
