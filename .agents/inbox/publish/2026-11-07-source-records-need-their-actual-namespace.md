# Source records need their actual published namespace

Search found [repository ownership and served namespaces](../2026-11-06-source-selection-must-not-pass-empty.md#keep-repository-ownership-separate-from-served-namespaces). This records a new concrete verifier mistake from #427.

**Evidence, 2026-11-07 UTC:** the first v0.25.1 public probe fetched `/docs/img/gyropup/SOURCE.json` from the website and received404 after11 retained raw responses, with zero view/context acceptance. The released builder at main `a32c1e6700ab3c64f08c1f5441f01303498e103d` copies only SVG/PNG/JPEG/GIF/WebP from `docs/img`; it never promised a website JSON route. The four ordinary model/card assets already matched released Git. Independent review accepted the exact namespace correction: obtain SOURCE through immutable `raw.githubusercontent.com/Valpatel/cad-agent/<actual-main>/docs/img/gyropup/SOURCE.json`, asserting exact final URL, no redirect and released Git bytes. The four actual website assets and all source/model/banner bindings stayed unchanged ([review](https://github.com/Valpatel/cad-agent/issues/427#issuecomment-6705108925)).

**Cause:** the verifier inferred a public route from repository ownership instead of reading the pinned producer's copy contract. The404 was a verifier namespace error, not evidence of a product, cache or deployment failure.

**Recorded request/output:** `GET https://cad-agent.valpatel.com/docs/img/gyropup/SOURCE.json` →404; corrected `GET https://raw.githubusercontent.com/Valpatel/cad-agent/a32c1e6700ab3c64f08c1f5441f01303498e103d/docs/img/gyropup/SOURCE.json` →200,1308 bytes, SHA256 `12e50e9bc8ddb85f1293692a51e95d2638e283d5d1da26fd65018d12c090568e`. Both were retained by the actual Node HTTP consumer before assertions, not inferred from URL strings.

**Rule:** derive each expected artifact location from the released producer. Distinguish ordinary served assets from immutable source metadata; record both hosts/routes explicitly. Keep source metadata byte binding and actual ordinary-site asset comparisons. Save raw failures before assertions and preserve the original failed attempt when correcting the recipe.

**Limits:** a correct immutable source record does not prove the website served its associated model. Those four ordinary assets, actual viewer controls and both stable deployment revisions were separately checked in the complete accepted run ([actual acceptance](https://github.com/Valpatel/cad-agent/issues/427#issuecomment-6705278005)). No site route or cache setting was changed.

## A copied kit README also needs its own namespace

On 2026-11-07, #432 at `b6c7b16634e776ab82b434c0ac0813705926d34f` added `../../../tools/mermaid/README.md` to the kit README's credits. The repository path was correct, but the site also copies that README into `kit/README.md`. Actual Chromium job128380592823 ran `node --test tests/site/website-*.test.mjs`:130 passed, one failed with `kit/README.md → ../../../tools/mermaid/README.md` ([independent finding](https://github.com/Valpatel/cad-agent/pull/432#discussion_r4501363521)).

Use a canonical repository source URL for a producer that is not part of the copied kit. Preserve the existing Markdown-twin local-link validator and require the corrected built product to pass it; adding the missing repository file or accepting a relative pathname cannot establish its served destination. This was a pre-merge CI failure, not evidence that a bad production page had been accepted.

## Shared discovery must preserve the source model it projects

**Design checkpoint, 2026-11-12 UTC, #599.** Actual main `62187386` (the same tree as dev `a2d356de`) publishes 228 catalogue entries and 814 reference records. Catalogue search indexes card summaries rather than article sections: `counterbores` and `disassembly` return no cards despite their presence in Pitfalls and the requirements lesson. “Tools” names both a catalogue of CLI commands and a long command/Python API manual. Six external URLs occur in both catalogue and reference records with different adoption/read meanings; URL equality is not permission to collapse those records.

**Bounded design.** Make `/explore` the primary navigation entry; retain `/catalog` as its clearly linked deeper catalogue/compatibility view. Add an explicitly derived discovery projection from current catalogue items, canonical lesson/pitfall sections and all reference records, using the existing topic tree. Reuse `<cad-gallery>` for search, topic/type filters, URL state, accessible counts and compact grouped defaults. Show references as concise rows, not hundreds of large picture cards; use existing source-owned visuals for orientation. Results retain their canonical page/section/record destinations and clear type labels. Preserve current catalogue/reference machine feeds, IDs, aliases, Markdown twins and legacy filter URLs; do not promote records or merge evidence, adoption and area maturity. Simplify top navigation while keeping old routes reachable.

**Interfaces.** A compiler-owned `site-discovery.mjs` will build the derived projection and compact HTML from existing catalogue output, published page HTML and the reference compiler's loaded model. New machine output is separately named/schema-versioned, not a mutation of `catalog.json`. The catalogue compiler retains its existing compatibility view for old kind/status/licence/maturity links. No search service, dependency, remote runtime fetch or hand-maintained second content registry.

**Meaningful experiment/check plan.** Test actual producer output, not only fixtures: a hidden body incident must become discoverable with a stable deep link; every canonical reference occurs exactly once in the projection; all source feeds/records retain their identities and counts; shared URLs retain separate source/adoption labels. Negative controls cover absent terms, unknown topics, invalid URLs/markup and snippet-only records masquerading as checked evidence. Check inherited catalogue filters/history, reference deep links/filters, no-script fallback, keyboard/mobile controls, density and source readability. Reserve a capped browser lane for 320 px and desktop light/dark checks and use existing width/readability predicates on actual prerendered assets. Independent experiments and exact-head GPT-6 review precede any merge; normal CI and public release proof remain required.

**Limits.** This is discovery and presentation, not another knowledge promotion, manufacturing API or universal full-text search claim. The existing source tables and source-evidence boundaries remain authoritative. Work is tracked under #599; the shared coordinator lease is not released by this author.

**Prototype evidence, #599:** the original derived feed at `/catalog/discovery.json` failed the existing catalogue-area consumer (which enumerates `/catalog/*.json` as area-schema files). The separately versioned projection moved to `/discovery.json`; no old schema/consumer exemption was added. Independent original-CSP preview also exposed absolute canonical demo-cover URLs in local/alternate-origin HTML. Keep canonical URLs in machine data, but emit same-origin paths for site-owned image markup and require `complete && naturalWidth > 0`; URL remapping or a visible image box is not load proof. Early no-script topic/type controls reloaded an unfiltered list and the fallback exposed 1199 links over 115000 px. Native collapsible groups now retain actual source links while JavaScript-only controls hide, rather than pretending query-only navigation filters static HTML.

**Loader-failure boundary, #599:** the corrected no-script view still failed when `/web/site.js` itself was blocked. JavaScript was enabled, so the catalogue's first-paint CSS hid overview overflow rows; the missing loader could not set `data-failed`. In Explore only, enhancement controls now remain hidden and native groups retain their full contents until `data-ready`. Test both the top-level loader and the gallery module failing, as well as JavaScript being disabled; a downstream failure handler cannot establish the upstream loader's fallback. The existing catalogue's first-paint contract is unchanged.

**Default-view reading measurement, #599:** the improved preview still failed the unchanged whole-page reading check: 2175 px with zero qualifying visuals, because its 110 × 80 px thumbnails were below the existing 120 × 80 px visual definition. The correction enlarges actual example thumbnails, uses two compact results per type in a two-column desktop browsing overview, and avoids repeating the already-present demo strip as another default list. Focused queries and explicit type views retain their original result flow. This is a readability/layout change, not a new visual exception, font reduction or adjusted reading threshold; acceptance must remeasure the existing predicate on the real producer.

**Independent final acceptance, #599 at `d3668afc`:** the real corrected view measured 1716 px desktop height, 2891 px phone height, eight compact default rows and three loaded qualifying example images. The unchanged reading predicate measured 955 px against 1200 px, with no overflow. Focused counterbores search retained its three practical entries and one source; all three script/failure modes preserved native access to the exact PEM record without dead controls. The owned bounded browser unit was inactive with an empty control group. [Recoverable public receipt](https://github.com/Valpatel/cad-agent/issues/599#issuecomment-6811832942). This is UI/source-navigation evidence, not another source read, promotion or physical qualification.
