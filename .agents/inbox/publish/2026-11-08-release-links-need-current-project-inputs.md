# A whole-set link needs a current native project, not a nearby filename

- **Evidence (2026-11-08 UTC):** The existing print-release consumer was given a genuine tiny two-plate native 3MF with TEST-ONLY settings. `test_release_links_the_complete_current_native_print_set` failed because the emitted page had no `cad/demo-plates.3mf` link. The publisher only iterated named per-part suffixes and explicit `extra_cad`; the generated project was outside that list. This was a missing link, not evidence that the old publisher accepted a stale whole-set project.
- **Correction:** Reuse the existing plate writer/reader and generated record. Bind the same STL bytes loaded by the exporter plus resolved layout/settings inputs; expose the project only when that record, native artifact, released quantities and actual plate readback agree. Withhold the link on stale/missing/unsupported inputs instead of rescuing the previous release copy. Nine actual consumer fault cases cover changed mesh, layout, quantity, profile, per-part override, old record, hash, corrupt archive and disabled plates.
- **Rule:** A native project is a distinct handoff from the per-part files. Keep per-part estimates separate from unrecorded plate totals; make GUI and physical acceptance explicit. Do not regenerate immutable numbered-specimen identities merely to fabricate fresh evidence for an old batch.
- **Limits:** These are small NumPy/ZIP consumer controls, not a CAD kernel run, slicer, GUI opening, printer operation or physical qualification. The existing numbered-coupon native/identity proofs and strict settings-export checks are retained. Actual exporter coverage with trimesh and exact whole CI remain required before acceptance.
