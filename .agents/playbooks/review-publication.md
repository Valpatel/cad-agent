# Publishing review evidence without repeatedly restarting CI

1. Inspect workflow triggers and concurrency before diagnosing cancelled checks.
2. Finish the implementation, validation evidence and PR description, then push the final source checkpoint.
3. While final checks run, append status receipts as comments. In this repo, description edits restart Python CI because `edited` also covers base-branch retargeting.
4. If a description correction or retarget is needed, make it once and wait for the replacement run. Never treat the cancelled predecessor as a passing result.
5. Merge only under the repository rules, with independent review, resolved conversations and current-head checks complete. Run live gates from a real current-dev Git checkout; a plain source archive cannot satisfy the main release path. Require the expected names and inspect every current applicable check instance; do not assume a fixed total or hide a non-success duplicate ([guard boundaries](../inbox/publish/2026-11-07-release-guards-need-current-boundaries.md)).
   Retire incorporated remote topic and release branches as part of each completed merge into `main`: verify that main contains each exact tip, use expected-tip leases, and preserve active work and local checkouts. A changed tip requires a fresh check. Branch retirement does not establish publication or issue acceptance; track those separately.
6. Reference unfinished broader work with `Refs #N` or “#N remains open”. Reserve automatic-closing syntax for completed acceptance; negating the sentence does not disable GitHub's keyword parser. Check the actual default branch and verify issue state after merge ([observed mistaken closure](../inbox/2026-11-07-negated-closing-keywords-still-close-issues.md)).
7. Before public calls, bind the inspected existing runtime/browser and derive each ordinary asset or immutable source-record route from the pinned producer, not its repository path ([runtime incident](../inbox/publish/2026-11-07-publication-consumers-need-explicit-runtimes.md), [namespace incident](../inbox/publish/2026-11-07-source-records-need-their-actual-namespace.md)). Preflight selected source sizes and rendered assertions before public calls: use bounded source-reader buffers, check visible link labels separately from their targets, and exercise wrong/missing-target controls ([consumer preflight](../inbox/publish/2026-11-07-release-guards-need-current-boundaries.md#preflight-source-sizes-and-rendered-assertions-before-public-verification)). Save raw responses before assertions and keep failed attempts distinct from corrected complete runs.
8. Preserve unexplained browser failures and diagnose their actual request/CSP evidence before any continuation. A reviewed finite classifier may separately retain an exact enforced provider block, with negative controls and zero external responses; all other errors stay blocking. Such acceptance does not fix provider injection or authorize CSP/settings changes ([diagnostic and limits](../inbox/publish/2026-11-07-provider-failures-need-matching-csp-evidence.md)).
   Match closeout to the issue's actual acceptance criteria. Preserve failures in a broader optional campaign without turning it into an additional global merge gate or claiming its acceptance from a narrower success ([finite scope evidence](../inbox/publish/2026-11-07-provider-failures-need-matching-csp-evidence.md#webkit-can-report-an-enforced-block-without-requestfailed)).

9. Review merge/deployment operators statically. Do not import them or execute selected assignments/definitions: they can call the mutation while omitting its guards and intent receipt. Use literal fixtures and individually inspected pure logic for controls; the reviewer must have no operational write path in that control. Unexpected execution requires preserved state and a fresh independent disposition before continuation ([actual reviewer incident](../inbox/2026-11-06-failed-prechecks-must-stop-mutations.md#a-reviewer-extraction-can-execute-mutation-assignments)).
