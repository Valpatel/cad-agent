# Publishing review evidence without repeatedly restarting CI

1. Inspect workflow triggers and concurrency before diagnosing cancelled checks. For zero-job startup failures, inspect the actual annotation and exact workflow/head before choosing any bounded infrastructure recovery; CLI heuristic explanations and cached annotations are not a diagnosis. Preserve each outcome and do not turn one recovery into a retry loop ([startup evidence](../inbox/publish/2026-11-07-release-guards-need-current-boundaries.md#inspect-actual-startup-annotations-before-a-bounded-recovery)).
2. Finish the implementation, validation evidence and PR description, then push the final source checkpoint.
   Parse any new changelog fragment with `tests/repo/test_cut_release.py`; ordinary Markdown headings are not
   release-section headings. Supply-chain additions need their actual report rows in the PR body.
3. While final checks run, append status receipts as comments. In this repo, description edits restart Python CI because `edited` also covers base-branch retargeting.
   Use `gh pr comment --body-file` or `gh issue comment --body-file` for ordinary timeline comments and read back the created comment/target. Do not substitute the issue-update API route: it can replace the description ([observed wrong-resource write](../inbox/2026-11-06-failed-prechecks-must-stop-mutations.md#a-comment-must-target-the-comment-resource)).
4. If a description correction or retarget is needed, make it once and wait for the replacement run. Never treat the cancelled predecessor as a passing result.
5. Merge only under the repository rules, with independent review, resolved conversations and current-head checks complete. Read back the posted exact-head review and validate that its marker is the last non-empty line with the existing parser before requesting the ordinary Actions refresh ([placement incident](../inbox/publish/2026-11-07-release-guards-need-current-boundaries.md#read-back-the-verdicts-last-non-empty-line)). Run live gates from a real current-dev Git checkout; a plain source archive cannot satisfy the main release path. Require the expected names and inspect every current applicable check instance; do not assume a fixed total or hide a non-success duplicate ([guard boundaries](../inbox/publish/2026-11-07-release-guards-need-current-boundaries.md)). Persist the exact-head preflight inputs, live-gate output and exit status before mutation. Keep mutation inside the same checked program after all explicit runtime checks, or issue it separately only after inspecting a successful preflight receipt; unchecked shell newlines can hide a failed guard behind a successful merge ([PR531 recurrence](../inbox/2026-11-06-failed-prechecks-must-stop-mutations.md#a-successful-merge-does-not-make-a-failed-auxiliary-preflight-pass)).
   Run the local live-gate command **without `--post`**. Actions owns posting the app-bound statuses; use the existing workflow review refresh when needed, then verify its results ([expected-app rejection](../inbox/publish/2026-11-07-release-guards-need-current-boundaries.md#local-live-verification-must-not-post-actions-owned-statuses)).
   Retire incorporated remote topic and release branches as part of each completed merge into `main`: verify that main contains each exact tip, use expected-tip leases, and preserve active work and local checkouts. A changed tip requires a fresh check. Branch retirement does not establish publication or issue acceptance; track those separately.
   For a remote-only retirement, do not fetch or write local refs during preflight: use existing objects for ancestry and read-only remote tip queries. Mandatory gates use explicit runtime checks that survive Python `-O`/`PYTHONOPTIMIZE`; run an optimized wrong-tip negative control with no operational write path. Before the network mutation, exclusively create and flush/fsync a private one-shot attempt marker. Use an atomic exact-tip CAS deletion against the verified anonymous repository URL to preserve local tracking refs. An attempted or uncertain result spends the marker; inspect state before any separately reviewed continuation ([optimization and scope incident](../inbox/publish/2026-11-07-release-guards-need-current-boundaries.md#enforce-retirement-boundaries-under-optimized-python)).
6. Reference unfinished broader work with `Refs #N` or “#N remains open”. Reserve automatic-closing syntax for completed acceptance; negating the sentence does not disable GitHub's keyword parser. Check the actual default branch and verify issue state after merge ([observed mistaken closure](../inbox/2026-11-07-negated-closing-keywords-still-close-issues.md)).
7. Before public calls, bind the inspected existing runtime/browser and derive each ordinary asset or immutable source-record route from the pinned producer, not its repository path ([runtime incident](../inbox/publish/2026-11-07-publication-consumers-need-explicit-runtimes.md), [namespace incident](../inbox/publish/2026-11-07-source-records-need-their-actual-namespace.md)). Preflight selected source sizes and rendered assertions before public calls: use bounded source-reader buffers, check visible link labels separately from their targets, and exercise wrong/missing-target controls ([consumer preflight](../inbox/publish/2026-11-07-release-guards-need-current-boundaries.md#preflight-source-sizes-and-rendered-assertions-before-public-verification)). Save raw responses before assertions and keep failed attempts distinct from corrected complete runs.
   Verify published figures and data against the actual producer, including visibility/drawing controls when comparing graphs; choose a comparison justified for the actual renderer ([graph evidence](../inbox/agents/2026-11-10-reading-batches-need-the-release-and-page-consumers.md#published-reading-counts-need-their-visible-figures)). Bind provider completion to structured commit/environment/stage fields rather than presentation labels ([deployment evidence](../inbox/publish/2026-11-07-release-guards-need-current-boundaries.md#deployment-completion-needs-structured-stage-status)).
8. Preserve unexplained browser failures and diagnose their actual request/CSP evidence before any continuation. A reviewed finite classifier may separately retain an exact enforced provider block, with negative controls and zero external responses; all other errors stay blocking. Such acceptance does not fix provider injection or authorize CSP/settings changes ([diagnostic and limits](../inbox/publish/2026-11-07-provider-failures-need-matching-csp-evidence.md)).
   Match closeout to the issue's actual acceptance criteria. Preserve failures in a broader optional campaign without turning it into an additional global merge gate or claiming its acceptance from a narrower success ([finite scope evidence](../inbox/publish/2026-11-07-provider-failures-need-matching-csp-evidence.md#webkit-can-report-an-enforced-block-without-requestfailed)).

9. Review merge/deployment operators statically. Do not import them or execute selected assignments/definitions: they can call the mutation while omitting its guards and intent receipt. Use literal fixtures and individually inspected pure logic for controls; the reviewer must have no operational write path in that control. Unexpected execution requires preserved state and a fresh independent disposition before continuation ([actual reviewer incident](../inbox/2026-11-06-failed-prechecks-must-stop-mutations.md#a-reviewer-extraction-can-execute-mutation-assignments)).
