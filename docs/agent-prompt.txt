How to install cad-agent (github.com/Valpatel/cad-agent, MIT) and work with it:

1. Install, or update, in a terminal. It needs git, adds uv if missing, and
   puts the kit in ~/cad-agent, the cad-agent command in ~/.local/bin and the
   skills in ~/.claude/skills and ~/.agents/skills. Use the platform's
   pinned download and checksum-before-execution block at
   https://cad-agent.valpatel.com/docs/agent-workflow#install
   Stop on a failed download or checksum mismatch; do not pipe a download
   straight into a shell.
   Already installed? Run `cad-agent update` first. More tools: add
   --extras fea,sim (strength; airflow, topology, renders), robot, explore.
   Fetch pages with curl or your web tool; from Python, send a User-Agent
   header, because the site blocks Python urllib's default one.
2. After installation, read `~/cad-agent/docs/agent-prompt.txt` in full
   from the installed checkout before designing. A web summary can omit
   requirements. Use your chosen checkout if CAD_AGENT_DIR differs.
   Look before you write code: fetch cad-agent.valpatel.com/llms.txt, then
   the page or catalog/<area>.json it points to (any page also as .md),
   and `cad-agent <command> --help`. Skills: ~/cad-agent/.agents/skills/*/SKILL.md.
3. Build with the kit's tested commands and checks, not formulas from
   memory. Start with `cad-agent init my-part` and change it; then
   `cad-agent all` builds, exports and runs every check. Before drawing a
   feature, run `cad-agent rules <feature>` (or `cad-agent choose joining`)
   and design to the card. Say what each
   check assumes: CAD and simulation narrow a design down, they do not
   prove that a printed part fits or holds.
4. Give back, through GitHub only: cad-agent collects no telemetry. When a
   tool is missing or wrong, you find a better source or you learn a lesson,
   write cad-agent-report.md with these headings: Model, Harness, cad-agent
   commit (git -C "$HOME/cad-agent" rev-parse --short HEAD), Layer (the
   cad-agent tool, or the upstream it wraps, with its version), Building,
   Missing or learned, Sources (links), Confidence (low, medium or high).
   Leave out anything private. Show it to your user, and send it only if
   they say yes: best as a PR into dev from a fork (a test, a source, a
   lesson or a fix; fill in the template's "Made with"), else as an issue:
   gh issue create -R Valpatel/cad-agent -t "Agent report: <topic>" -F cad-agent-report.md
