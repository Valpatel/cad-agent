# Use and maintain SCADA locally

A complete cad-agent Git checkout physically contains the SCADA runtime source,
models, schemas, examples, artwork, thumbnails, generators, tests and guides. It
runs from that checkout without another source repository or hosted service. Use a
long-lived checkout on the home machine when installing linked agent skills.

## Run the source examples

From the cad-agent repository root, serve the existing runtime source:

```sh
python -m http.server 8000 --directory software/cadagent/webkit
```

Open `http://localhost:8000/scada/explorer/index.html?scenario=wastewater-digester`.
The host loads only local modules, styles and scenario assets. Enable sound
explicitly if desired. Use pan/zoom and the pinned Fit control inside the viewer;
long forms and the outer page may still scroll. A local HTTP server avoids the
browser-dependent behavior of ES modules opened with `file:` URLs.

The UI and simulation packages also expose ordinary package manifests under
`software/cadagent/webkit/scada/{ui,sim}/`. A local consumer may use those source
packages or create its own `npm pack` artifact under the included MIT license.
The runtime packages have no external JavaScript runtime dependencies. A runtime
export omits authoring tools/tests intentionally; it is not a complete development
checkout or a substitute for the local source copy.

## Distribution scope

The Python wheel and `cad-agent webkit` copy carry the complete browser SDK,
including SCADA modules, schemas, scenario definitions, local galleries, examples,
reference notes and complete license notices. Gallery and documentation paths in
package exports continue to resolve locally. The gallery makes this a larger SDK rather than a minimal viewer export; measure
the selected artifact when sizing a deployment. The source checkout also supplies
separate tools, tests and agent skills. A wheel is not the authoring checkout.

Assembly-guide exports select a smaller, explicit reader runtime and omit SCADA.
They still include their required model renderer, controls, assembly instructions,
decoders, styles and notices. Keep these two delivery scopes separate: do not
silently trim the full SDK, manufacture stripped SCADA package metadata, or add an
unused intermediate profile. Verify the actual artifact and its local imports,
not only the source package.

## Install authoring and review tools

The shared maintenance owner declares its own Node dependencies and lockfile:

```sh
npm --prefix tools/webkit/scada ci --ignore-scripts
npm --prefix tools/webkit/scada test
npm --prefix tools/webkit/scada run check:schema
npm --prefix tools/webkit/scada run check:metadata
npm --prefix tools/webkit/scada run check:default-baseline
```

Use Node.js 22.22.2+, 24.15.0+, or 26+ (the maintenance lockfile's supported range).
Browser captures use the Python environment's declared
requirements in `tools/webkit/scada/ui/requirements.txt`, plus a local `chromium`
binary or Playwright-installed Chromium. Install these development dependencies
before disconnecting a home machine. A browser's OS libraries also need to be
available; prerequisite discovery does not replace executing a real browser check.

```sh
python -m pip install -r tools/webkit/scada/ui/requirements.txt
python -m playwright install chromium
npm --prefix tools/webkit/scada run qa:viewer -- --help
```

The [tools map](../../../tools/webkit/scada/README.md) gives the exact generators,
checks and capture entrypoints. Their `--help` identifies supported output paths,
filters and browser options. Gallery and topology receipts are regenerated by
these owners rather than hand-edited.

## Install the canonical agent procedures

Use the existing installer from a stable cad-agent checkout:

```sh
cad-agent agents install --source /absolute/path/to/cad-agent
```

The installer reports local Node/npm and Python-Playwright/Chromium requirements
for the SCADA procedures. It checks local executables/modules without downloading
dependencies or contacting services. `--copy` copies skill instructions/resources;
linked repository guides still require the named checkout. A wheel alone does not
contain the canonical agent kit: supply `--source` when necessary.

The procedures cover component authoring, system authoring, equation/solver
replacement, visual review, documentation and isolated-consumer verification.
Their exact commands and source references live in the
[canonical skill map](../../../.agents/skills/README.md).

## Prove local independence

After preparing the checkout and development dependencies, disable network access
for a test run. Open the Explorer, change a valve/load, inject and repair a fault,
open its read-only observer, and verify both views share the same time/state.
Run model/schema/metadata checks and regenerate a selected gallery or topology
through the documented owner. Capture the exact source and dependency versions.
This tests physically present resources rather than a browser's accidental cache.

For a generated site or release, additionally test the actual exported directory
or archive with the source checkout unavailable. Reproducibility evidence should
bind the model/provider bytes, parameters, schemas and output hashes. UI previews
are not physical validation of the system.

External publications and upstream repositories have separate acquisition and
rights requirements; see [resources and growth](resources-and-growth.md).
